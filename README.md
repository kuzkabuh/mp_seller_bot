mp_seller_bot
Описание

mp_seller_bot — это Telegram‑бот для продавцов Wildberries и Ozon,
который автоматически отслеживает новые заказы (FBS/FBO) и
уведомляет о них. Бот позволяет подключать и отключать
учётные данные маркетплейсов, предоставляет базовую аналитику по
количеству заказов за последние 7 дней и выводит простые
подсказки по увеличению выручки.

Возможности

Подключение API‑ключей Wildberries (FBS) и пары client_id/API‑ключ для Ozon.

Безопасное хранение ключей с использованием шифрования Fernet.

Регулярный опрос маркетплейсов и отправка уведомлений о новых
заказах/отправлениях (FBS и FBO).

Дедупликация заказов: каждый заказ учитывается один раз.

Команды для получения статистики (количество событий за 7 дней) и
подсказок по увеличению выручки.

Возможность работы в webhook‑режиме или через polling.

Требования

Python 3.11 или новее (при запуске без Docker).

PostgreSQL 13+ и Redis (опционально для aiogram).

Docker и docker‑compose (если планируется запуск через контейнеры).

Telegram‑бот‑токен, полученный у @BotFather
.

Секретный ключ для Fernet (генерируется один раз).

Быстрый старт
1. Клонирование репозитория
git clone https://github.com/kuzkabuh/mp_seller_bot.git
cd mp_seller_bot

2. Настройка переменных окружения

Создайте файл .env в корне проекта на основе шаблона
.env.example и заполните его. Минимальный набор переменных:

Переменная	Описание
BOT_TOKEN	Токен Telegram‑бота от BotFather
FERNET_KEY	Ключ для шифрования API‑токенов. Сгенерировать можно командой python -c 'from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())'
POSTGRES_HOST	Хост базы данных PostgreSQL
POSTGRES_PORT	Порт базы данных (обычно 5432)
POSTGRES_DB	Имя базы данных
POSTGRES_USER	Пользователь для подключения к БД
POSTGRES_PASSWORD	Пароль пользователя
REDIS_HOST	Хост Redis (если используется для aiogram; можно оставить пустым)
REDIS_PORT	Порт Redis
WEBHOOK_BASE_URL	Базовый URL для webhook (например, https://your.bot.host), если используется webhook
WEBHOOK_SECRET	Секретный сегмент URL webhook для дополнительной безопасности

Дополнительные настройки (интервал опроса, порты) можно оставить
по умолчанию или изменить в .env.

3. Запуск в Docker

Самый простой способ запустить бот — воспользоваться docker-compose.
В каталоге проекта уже есть docker-compose.yml, который
поднимает PostgreSQL, Redis, бот и nginx‑прокси.

docker compose up -d --build


Команда соберёт образы, создаст необходимые сервисы и запустит их.
Проверить логи можно так:

docker compose logs -f bot


По умолчанию бот будет доступен по webhook (если указан
WEBHOOK_BASE_URL) либо перейдёт в polling‑режим. Nginx слушает
порт 80 и проксирует запросы к боту на порт 8000.

4. Запуск без Docker

Установите зависимости:

python -m venv venv
source venv/bin/activate
pip install -r requirements.txt


Убедитесь, что запущен PostgreSQL и создана база данных, соответствующая
значениям в .env.

Инициализируйте таблицы:

python -c "from app.db import init_db; import asyncio; asyncio.run(init_db())"


Запустите бота:

python -m app.main


Бот автоматически выберет режим polling или webhook в зависимости
от переменных окружения.

Использование

После запуска добавьте бота в Telegram и отправьте команду
/start. В появившемся меню доступны следующие действия:

Подключить Wildberries — отправьте API‑ключ WB одним
сообщением. Бот сохранит его в зашифрованном виде и начнёт
уведомлять о новых FBS/FBO заказах.

Подключить Ozon — отправьте client_id и api_key,
разделённые пробелом или двоеточием (например,
123456:abcdef...). Бот сохранит данные и будет
уведомлять о новых отправлениях.

Отключить WB/Ozon — временно отключает мониторинг
соответствующего маркетплейса.

Аналитика за 7 дней — показывает количество заказов по
каждой схеме и маркетплейсу за последнюю неделю.

Подсказки по выручке — выводит статические советы по
увеличению продаж.

Версионирование

Проект использует SemVer
 для
управления версиями: MAJOR.MINOR.PATCH. Номер версии
указывается в комментариях в каждом файле. При добавлении новых
функций увеличивайте MINOR, при изменении API — MAJOR, при
исправлении багов — PATCH. Это упрощает отслеживание изменений и
обновлений.

Обновление бота

Чтобы обновить существующий развёрнутый бот до последней версии:

Обновите исходный код (например, git pull).

Пересоберите и перезапустите контейнер bot:

docker compose build bot
docker compose up -d bot


При запуске вручную просто перезапустите процесс python -m app.main.

Безопасность

API‑ключи и client_id хранятся только в зашифрованном виде.

Сообщения, содержащие ключи, удаляются из чата сразу после
сохранения.

Веб‑сервер (nginx) проксирует запросы только к публичным
эндпоинтам бота (/webhook/... и /health).

Настройте сложный FERNET_KEY и сохраняйте его в безопасном месте.

Поддержка слабых серверов

Бот оптимизирован для работы на серверах с ограниченными
ресурсами:

Используется асинхронный http‑клиент httpx и асинхронный ORM
SQLAlchemy, что снижает блокировки.

Опрос маркетплейсов выполняется с регулируемым интервалом
(POLL_INTERVAL_SECONDS), по умолчанию 30 секунд — можно увеличить,
чтобы уменьшить нагрузку.

Уведомления отправляются только при обнаружении новых
событий, исключая повторные запросы.

Дополнительные сведения

Для интеграции бота с другими системами или расширения
функциональности (например, добавление аналитики по выручке,
поддержка новых маркетплейсов) следуйте модульной структуре
проекта: добавляйте сервисы в app/services, новые модели — в
app/db/models.py, а бизнес‑логику — в соответствующие
обработчики app/bot/handlers.
